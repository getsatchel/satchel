# Satchel 0.4.0

Admins manage who can use a workspace from the UI, curators write instructions that shape how
agents work, and a session with several questions now reads as one question at a time. Sign-in
has its own page, and the sidebar is shorter.

> **Status:** pre-alpha. Expect breaking changes between 0.x releases. This release adds two
> migrations, one of which backfills existing sessions: see [Upgrading from 0.3.0](#upgrading-from-030).

## Install

```bash
uv tool install satchel-server     # or: uv tool upgrade satchel-server
satchel init --example jaffle
satchel up
```

Container image and Helm chart:

```bash
docker pull ghcr.io/getsatchel/satchel:0.4.0
helm install satchel oci://ghcr.io/getsatchel/charts/satchel --version 0.4.0 -n satchel --create-namespace -f my-values.yaml
```

This release ships with `satchel-adapter-sdk` 1.2.1 (IR 1.0.0).

## New

- **Members.** **Settings > Members** (admins) lists everyone in the workspace with their role and
  last activity.
  - **Invite** people by email with a role. An invite is a member with an email and no sign-in
    yet; their first sign-in with that verified email links the account.
  - Change a member's **role**, **deactivate** or **reactivate** them, and remove an invite nobody
    has used. A deactivated member's tokens, sessions and sign-ins are refused until they are
    reactivated; their sessions, feedback and context changes stay.
  - **Sign-in** on the same tab sets whether people who were not invited are refused or join as
    explorers, optionally only from some email domains (the setting `satchel workspace auth`
    changes).
  - You cannot change your own role or deactivate yourself, and a workspace always keeps one
    active admin.
  - API: `GET`/`POST /v1/members`, `PATCH`/`DELETE /v1/members/{id}`, `PUT /v1/members/sign-in`.
- **Agent instructions.** **Curate > Agent instructions** is where curators write how agents should
  work in this workspace: tone, when to prefer a metric, caveats to always mention, how to present
  results.
  - It is a versioned item (`agent.md`, also at the root of a context repo), so it goes through
    draft, preview, the eval gate and publish like any context, and can be rolled back.
  - Agents receive the published text from `start_analysis` (`agent_instructions`) and at the top
    of every context pack, tagged `[ctx:agent.md@vN]`. Satchel's own workflow still applies, and
    wins where the two conflict.
  - Only people write it: agents cannot propose it and curation never drafts it.
- **Questions within a session.** Agents often keep one session for a whole conversation. Satchel
  now groups a session's tool calls into one **turn** per question (the `session_turn` table).
  - **Sessions** lists one row per question; switch to **Conversations** for one row per session.
  - The session inspector steps through a conversation's questions and shows each one's answer,
    tool calls, signals and feedback.
  - Signals record the question they came from, so curation clusters them with that question.
  - `GET /v1/turns` lists questions; session details include their turns.
- **Sign-in page.** `/auth/login` is a page with one "Sign in with …" button instead of an
  immediate redirect to the identity provider.
  - Signing out shows "You're signed out." instead of sending you back to the provider.
  - Without an identity provider, the page says which `SATCHEL_OIDC_*` settings to set.
  - A refused sign-in names the account that signed in and says to ask an admin for an invite.
  - `SATCHEL_OIDC_DISPLAY_NAME` names the provider on the button; otherwise it is guessed from the
    issuer (Google, Microsoft, Okta, Auth0, Cognito, Keycloak).

## Changes

- **Shorter sidebar.** Nine entries instead of twelve:
  - **Releases** has two tabs: Changes (unpublished changes, preview, evals, publish) and History.
  - **Sessions** has a **Usage** tab (formerly Observability).
  - **Jobs** is a tab under **Settings**, for curators and admins.
  - The old addresses redirect: `/changes` to `/releases`, `/observability` to
    `/sessions?tab=usage`, `/jobs` to `/settings?tab=jobs`. Query strings are kept, so preview
    links from the GitHub Action still work.
- **No repeated result tables.** When a query result is shown to the user as an interactive Satchel
  table, `run_sql`, `query_metrics` and `get_result` tell the agent not to repeat its rows, and the
  workflow instructions say the same. Answers in Claude no longer show the widget and then the
  same table again.
- **Plainer setup dialogs.** Adding a warehouse connection is one form; adding a source is three
  short steps. A new connection offers **Crawl**; a new source opens its page. The Dashboard lists
  only the setup steps that are left.
- **Curator UI.** Dialogs are bottom sheets on phones and move focus to their first field; the UI
  honours reduced motion. `ui/DESIGN.md` is rewritten to describe the UI as built.
- **Server pages.** Missing UI files return 404 instead of the app page, and the favicon's URL is
  hashed so a new icon is picked up.
- **Docs.** Every screenshot in `docs/screenshots/` is recaptured for the new navigation.

## Upgrading from 0.3.0

**Back up the database first**, as for any upgrade.

```bash
uv tool upgrade satchel-server
satchel db upgrade
```

The migrations are `0017` (the `session_turn` table, `tool_call.turn_id` and `signal.turn_id`) and
`0018` (`app_user.disabled_at`). Run `satchel db upgrade`, or let the Helm chart's migration job
run, before starting the new version.

- `0017` splits every existing session into questions, reading each session's tool calls. On a
  large database it takes longer than the usual migration.
- Signals recorded before the upgrade are not assigned a question; curation uses their session's
  first question for them, as before.

After the upgrade:

- Links or bookmarks to `/auth/login` show the sign-in page; people click **Sign in** once more.
  Scripts that relied on the redirect should use `/auth/login/start` (same parameters).
- Bookmarks to `/changes`, `/observability` and `/jobs` redirect to their new tabs.
