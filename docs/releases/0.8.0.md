# Satchel 0.8.0

A hardening release. Satchel can now run without storing any credentials, and it adds the
controls a deployment without a WAF in front needs.

- **Store nothing.** Warehouse passwords, model API keys and source tokens can live in AWS
  Secrets Manager or GCP Secret Manager, and Satchel reads them when it needs them. Models can
  run on **Amazon Bedrock** or **Vertex AI** with no API key at all.
  `SATCHEL_SECRETS=references` makes Satchel refuse to store any secret.
- **Hardening.** Every response gets security headers, and the UI gets a strict
  Content-Security-Policy. Sign-in, OAuth and `/mcp` are rate limited. Connection **Test** warns
  when the warehouse role can write. Images are signed, with an SBOM and provenance.
- **Evals** show which model a run will use, and Gemini evals work.

> **Status:** pre-alpha. Expect breaking changes between 0.x releases. Two migrations (0020, 0021).

## Install

```bash
uv tool install satchel-server     # or: uv tool upgrade satchel-server
```

```bash
docker pull ghcr.io/getsatchel/satchel:0.8.0
helm upgrade satchel oci://ghcr.io/getsatchel/charts/satchel --version 0.8.0 -n satchel -f my-values.yaml
```

## Changes

### Secrets from a secret manager (#70, #73)

Every secret field also takes a **reference**, so Satchel keeps the reference and never the value.
The fields are a connection's password or key, a model's API key, and a source's git or Cube
token. A reference looks like:
- `aws-sm:<name or ARN>[#field]`;
- `gcp-sm:projects/<p>/secrets/<s>[#field]`.

Satchel reads the secret with the server's own cloud identity when it needs it, and caches it for
`SATCHEL_SECRET_CACHE_S` (default 300 s). **Test** always reads it fresh, so a rotated secret
shows straight away.

- **Allow list.** The UI and API accept only references that match `SATCHEL_SECRET_REF_ALLOW`.
  Unset, references are off. `env:` references stay CLI-only.
- **`SATCHEL_SECRETS=references`** refuses every secret value. `satchel doctor` lists any stored
  before the switch.
- **In the UI:** Connections and Models have a **From a secret manager** option, and source token
  fields take a reference directly.
- **Terraform:** `secret_ref_prefix` grants the runtime identity read access to that prefix only,
  and sets the allow list. It covers the EKS, GKE and Cloud Run modules. A prefix that would
  cover Satchel's own secrets fails `terraform plan`.
- **Helm:** `secretRefs.allow` / `secretRefs.mode`.

See [Secrets](../deploy/secrets.md).

### Models without API keys (#77)

| Provider | Models | Identity | Terraform |
|---|---|---|---|
| **Amazon Bedrock** | Claude; the model is a Bedrock model or inference profile id | the server's AWS role | `enable_bedrock` |
| **Vertex AI** | Claude (`claude-...`) or Gemini | the server's Google service account | `enable_vertex_ai` |

- **Where to set them:** add them under **Settings > Models**, or for the whole deployment with
  `SATCHEL_CHAT_PROVIDER=bedrock|vertex` and `SATCHEL_CHAT_REGION` / `SATCHEL_CHAT_PROJECT`. In
  the chart, they're `chat.region` / `chat.project`.
- **Before the first call:** model access must be granted in the Bedrock console, and Claude
  enabled in Vertex's Model Garden.

### Hardening (#74, #75, #76, #78)

- **Security headers.** Every response gets `X-Content-Type-Options: nosniff`,
  `X-Frame-Options: DENY`, `Referrer-Policy`, and HSTS when `SATCHEL_PUBLIC_URL` is https.
- **The UI page's Content-Security-Policy:**
  - scripts come only from Satchel, plus its one inline script, allowed by hash;
  - no `eval`;
  - no framing.
- **Rate limits.** Over the limit, Satchel answers `429` with `Retry-After`.

  | Routes | Keyed by | Limit |
  |---|---|---|
  | Sign-in and `/oauth/*` | client IP | 30 a minute |
  | `/mcp` | bearer token | 600 a minute |

  Set them with `SATCHEL_RATE_LIMIT_AUTH_PER_MIN` / `_MCP_PER_MIN`, or in the chart with
  `rateLimits`. `0` turns one off.
- **The client address behind a proxy.** The new `SATCHEL_FORWARDED_ALLOW_IPS` says which proxies
  Satchel trusts for the client's address. The VM Compose file, the chart (`forwardedAllowIps`)
  and the Cloud Run module set it to trust their front proxy.
- **Write access.** Connection **Test** warns, without failing, when the role can change data:
  - on PostgreSQL, a superuser, or a role that can write any table or create tables;
  - on Snowflake, an admin role or write grants.
- **Test and Crawl results** now stay under the connection on the Connections list.
- **Images:**
  - signed with keyless cosign;
  - carry an SPDX SBOM and SLSA provenance
    ([Verifying the image](../deploy/container.md#verifying-the-image));
  - locked dependencies are audited weekly and on every lockfile change, and Dependabot proposes
    updates.

See [Security](../deploy/security.md).

### Evals (#71, #72)

- **Gemini evals work.** 0.7.0's Gemini connections passed **Test** but failed on the first tool
  call, with HTTP 400 "missing a thought_signature". The signature now goes back with each call.
- **The Evals page shows models.** It shows the agent and judge model, with **Manage models**, and
  each suite's pinned model.
- **Run picks from your models.** Run offers your configured models instead of a free-text
  override, and says which model the run will use.
- **A suite pinned to a model you don't have** now starts on the workspace's model; before, its
  cases were skipped. Satchel's demo `core` suite, pinned to Anthropic, is one.
- `GET /v1/evals/model` tells an API client the same thing.

## Upgrading from 0.7.x

The two migrations run the same way as before:
- **Helm:** the chart's pre-upgrade job.
- **VM:** `docker compose up -d` (the `db-upgrade` step).
- **Installed package:** run `satchel db upgrade` before restarting.

What they change:
- **0020** adds `llm_connection.api_key_ref`.
- **0021** adds `llm_connection.region` and `project`, and the `bedrock` / `vertex` providers.

**Rate limits are on by default. Check the client address first.** Behind a proxy that Satchel
doesn't trust, every request looks like it comes from the proxy. All sign-ins then share one
30-a-minute budget.
- The VM Compose file, the chart and the Cloud Run module now trust their proxy.
- On any other setup behind a proxy, set `SATCHEL_FORWARDED_ALLOW_IPS` to its address or CIDR
  (or `*` when only the proxy can reach Satchel). Otherwise, raise the limits or set them to `0`.

**Other changes to check:**
- **Framing:** the UI can no longer be shown inside another site's frame.
- **API responses:**
  - connections include `secret_ref`, null unless the secret is a reference;
  - a connection test returns `warnings`;
  - model connections include `api_key_ref`, `region` and `project`.
- **Secret values that look like references:** a secret starting with `aws-sm:` or `gcp-sm:` is
  now read as a reference.

On a VM:
1. Set `SATCHEL_IMAGE_TAG=0.8.0` in `.env`.
2. Copy the new `SATCHEL_FORWARDED_ALLOW_IPS` line from `docker-compose.yml`, or pull the updated
   file.
3. Run `docker compose pull && docker compose up -d && docker image prune -a -f`.

Everything in [0.7.0](0.7.0.md) applies when upgrading from 0.6.x.
