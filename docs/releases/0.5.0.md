# Satchel 0.5.0

In Claude and other MCP Apps clients, a question now ends with one Satchel **answer card**: the
headline, key points, the results as tabs and facts Satchel works out from the rows, instead of a
table per query. Everyone in a workspace gets a UI made for their role: explorers and analysts get a
home page that shows how to connect their agent, and see what their team asked. Inviting someone
gives you a link to send them, and on Amazon Cognito it can create their account too. Curation now
treats each question in a conversation on its own. The docs have a role matrix and live at
getsatchel.dev.

> **Status:** pre-alpha. Expect breaking changes between 0.x releases. This release has no new
> migrations, but it changes who can see sessions: see [Upgrading from 0.4.0](#upgrading-from-040).

## Install

```bash
uv tool install satchel-server     # or: uv tool upgrade satchel-server
satchel init --example jaffle
satchel up
```

Container image and Helm chart:

```bash
docker pull ghcr.io/getsatchel/satchel:0.5.0
helm install satchel oci://ghcr.io/getsatchel/charts/satchel --version 0.5.0 -n satchel --create-namespace -f my-values.yaml
```

This release ships with `satchel-adapter-sdk` 1.2.1 (IR 1.0.0).

## New

- **Answer card.** When the agent calls `report_answer`, clients with MCP Apps (Claude, ChatGPT,
  VS Code, Goose) show one card in Satchel's own look:
  - the question, the agent's `headline` and up to five `key_points` (new optional arguments; the
    headline defaults to `answer_summary`);
  - the results as tabs, chosen with the new `result_ids` argument, or by default the question's
    results that returned rows, each with its chart, table and SQL;
  - caveats, a confidence label when it is not high, **How this was answered** (every tool call of
    the question, empty and failed queries included), the context used, and 👍/👎 for the result
    shown.

  The agent is told the user sees the card, so its reply adds only what the card does not say. See
  [Cards in Claude](../reference/mcp-tools.md#cards-in-claude-and-other-mcp-apps-hosts).
- **Facts computed from the data.** `run_sql` and `query_metrics` work out facts from the rows,
  never with a model: the change over the period and on the previous one, the peak, low and
  average, the trend, an outlier, a last period that is not over yet, the top value's share of the
  total, and mostly empty columns. The agent gets them in the tool's text to cite, and the cards
  show them under **What Satchel noticed**, with the average and the peak and low drawn on the
  chart. Facts quote data values, so they are not kept with the tool call that other members see
  under **Sessions**.
- **A UI for every role.** Explorers and analysts no longer see the curator dashboard full of refused
  requests.
  - **Home** shows how to connect Claude (the connector URL and the Claude Code command, ready to
    copy), their recent questions, and how many glossary terms, golden queries, guides and
    documented tables their agent can use.
  - Their sidebar is Home, Library, Catalog and Sessions. Curators and admins keep the full sidebar.
  - A page that is not for your role says "This page is for curators" instead of showing errors, and
    buttons a role cannot use are hidden.
- **Analysts see the team's questions.** **Sessions** has an **Everyone / Mine** switch for analysts.
  Other people's questions are shown the way curators see them: SQL values masked, long text
  truncated, and sensitive sessions as metadata only. Explorers still see only their own.
- **Invite links.** After you invite someone under **Settings > Members**, the dialog shows a link to
  send them; invited rows have **Copy link**. It opens the sign-in page with the workspace chosen
  and passes their email to the identity provider as `login_hint`. The page says who was invited.
- **Cognito accounts on invite.** With `SATCHEL_OIDC_CREATE_USERS=true` and an Amazon Cognito issuer,
  inviting someone also creates their Cognito user, and Cognito emails a temporary password. The
  dialog shows, per address, whether it was created, already existed or failed; a failure never
  undoes the invite, and inviting the same email again retries it. The server needs
  `cognito-idp:AdminCreateUser` on the pool (the image already includes `boto3`).

## Changes

- **Query cards.** Each `run_sql`, `query_metrics` and `get_result` card is one line until opened
  with **Show result**: a title, the row count and the first fact. `run_sql` and `query_metrics`
  take an optional `title` (for example "Signups by month, 2025") instead of every card repeating
  the question, and a result with no rows says so instead of drawing an empty table. The tool
  descriptions ask agents to title each query, put related figures in one query and check columns
  with `describe_table` rather than with trial queries.
- **Curation per question.** Agents often keep one session for a conversation, and curation now
  works on each question in it:
  - **Golden queries** are judged on a question's own queries, feedback and answer, and carry that
    question. A 👎 on one question no longer holds back another.
  - **Inbox evidence** is one entry per question, with its own text, and links to that question in
    the session inspector.
  - The model drafting a suggestion sees only the questions its signals came from, plus the earlier
    questions' text so a follow-up makes sense.
  - **Proposals** show the question the agent was answering, and `record_user_feedback` rates the
    current question.
- **Session retention** counts from a conversation's latest question, so a conversation still in use
  is not deleted.
- **Mobile and accessibility.**
  - Larger touch targets on phones: buttons and inputs 40px, small buttons and segmented controls
    36px.
  - Keyboard support for tabs (arrow keys, Home, End). The phone menu keeps focus inside it, and
    Escape closes it.
  - Focus moves to Back when a detail opens on a phone, and returns to the row on Back.
  - Labels on the command palette and the code editors.
  - Pages that were cramped on phones are fixed: the Sessions filters, the Releases preview test
    box, and Settings > Connections and Models.
  - The light theme's green and amber are darker so their badges meet contrast guidelines; the
    result widget and the website use the same values.
- **Docs.**
  - The UI's Docs links open https://getsatchel.dev instead of GitHub.
  - *How Satchel works* has a **Roles** section with a role matrix.
  - *Configuration* covers Settings > Members and Settings > Jobs.
  - The CLI and environment references are checked against the code.
  - The README, the Claude guide and the MCP tools reference show the answer card, captured from the
    Jaffle Shop demo.
- **Evals** is a page for curators and admins. Analysts can still run evals from the CLI or the API.
- **License.** `LICENSE` and `sdk/LICENSE` name the copyright holder (The Satchel Authors), as `NOTICE` does.
- **Dependencies.** react-router-dom 7.18 (from 6.30; the UI was checked page by page) and opentelemetry-api 1.45.2.

## Fixes

- **`describe_table` on a table with two records of the same name.** A dbt or Cube source with no
  connection, or context imported before its connection was added, created a second table record
  with the same name as the crawled one, and `describe_table` refused it as ambiguous
  ("analytics.orders, analytics.orders"). They are now one table: the doc applies to the connected
  table and `list_tables` shows it once. A table that really is on several connections names them,
  and `describe_table` takes a `connection` argument to pick one; its result says which connection
  the table is on.

## Upgrading from 0.4.0

There are no migrations. Update the package or image and restart:

```bash
uv tool upgrade satchel-server      # local
```

On a VM, set `SATCHEL_IMAGE_TAG=0.5.0` in `.env`, then `docker compose pull && docker compose up -d`.

Behaviour that changes on upgrade:

- **Analysts can see everyone's questions** under **Sessions**, redacted as curators see them. Before,
  they saw only their own. If some members should not see their colleagues' questions, give them
  the explorer role, or mark sensitive sessions under **Sessions** (admins).
- **Session retention** no longer deletes a conversation whose latest question is within the
  retention period, even if it started earlier.
- Sessions that already produced a golden-query candidate before the upgrade are not judged again.
- **Cards in Claude.** Query results collapse to one line, and `report_answer` shows the answer
  card. Agents follow the new tool descriptions without any change on your side; clients without MCP
  Apps get the same text answers as before. The widget now bundles Satchel's fonts (685 KiB).
