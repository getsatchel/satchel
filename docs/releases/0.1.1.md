# Satchel 0.1.1

Satchel is now on PyPI as **`satchel-server`**, and the package includes the built curator UI.

> **Status:** pre-alpha. Expect breaking changes between 0.x releases.

## Install

```bash
uv tool install satchel-server     # the command is still `satchel`
satchel init --example jaffle
satchel up
```

Container image and Helm chart:

```bash
docker pull ghcr.io/getsatchel/satchel:0.1.1
helm install satchel oci://ghcr.io/getsatchel/charts/satchel --version 0.1.1 -n satchel --create-namespace -f my-values.yaml
```

This release ships with `satchel-adapter-sdk` 1.2.1 (IR 1.0.0).

## Changes

- **Published to PyPI as `satchel-server`.** The PyPI name `satchel` belongs to an unrelated project. Only the package name changed: the command is `satchel` and the import package is `satchel`, as before.
- **The UI is included.** A 0.1.0 install from git had no built UI, so `satchel up` showed a "no built curator UI" page. The PyPI wheel is built after the UI and bundles it.
- **Install hints no longer point at the wrong package.** Messages about missing extras (S3, GCS, BigQuery, Snowflake, connection kinds, built-in source adapters) and the pip branch of `satchel upgrade` said `pip install satchel`, which would have installed the unrelated project. They now say `satchel-server[<extra>]==<version>`.
- **Release notes links work on GitHub.** The release page now links to the docs of the tagged version.

## Upgrading from 0.1.0

If you installed 0.1.0 with `uv tool install "satchel @ git+…"`, switch to the PyPI package once:

```bash
uv tool uninstall satchel && uv tool install satchel-server
satchel db upgrade
```

Your config and the MCP client entries written by `satchel connect` keep working: the command is still `satchel`,
at the same path. There are no database migrations in this release. Container and Helm users only need to move to
`0.1.1`.
