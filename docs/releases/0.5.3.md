# Satchel 0.5.3

Charts that make sense for the data. A ranking of customers that had date columns came out as a
line of `customer_id` over time, with facts about the id.

> **Status:** pre-alpha. Expect breaking changes between 0.x releases. No migrations.

## Install

```bash
uv tool install satchel-server     # or: uv tool upgrade satchel-server
```

```bash
docker pull ghcr.io/getsatchel/satchel:0.5.3
helm upgrade satchel oci://ghcr.io/getsatchel/charts/satchel --version 0.5.3 -n satchel -f my-values.yaml
```

## Fixes

- **The server picks the chart, and the facts follow it.** The result payload carries the chart to
  draw, and "What Satchel noticed" describes the same columns:
  - a **line** only for a time series, one row per date;
  - **bars** for one row per thing (a status, a customer), up to 30, labelled by its name
    columns or id, in the result's order;
  - **no chart** for several rows per date, a list with no measure, or more than 30 things.

  Identifier columns (`customer_id`, `*_key`) are never plotted or described as numbers. A money
  column is the measure when there is one.
- **Readable axes.** A y-axis title, round ticks (0, 500, 1k), dates along the x axis and bar
  labels that fit.
- **Tables when they add something.** When the chart already shows every column, the table folds
  behind **Show table**.
- Facts about a breakdown say what they cover ("11% of the 11,932.50 total of these 10").

## For contributors

`scripts/widget_fixtures.py` saves result payloads from the Jaffle Shop data. `npm run gallery` in
`ui-widgets/` screenshots each of them in the widget, and `test/charts.e2e.mjs` checks them.

## Upgrading from 0.5.2

Update the package or image and restart. On a VM, set `SATCHEL_IMAGE_TAG=0.5.3` in `.env`, then
`docker compose pull && docker compose up -d`. Start a new chat in Claude to pick up the new widget.

Everything in 0.5.0 to 0.5.2 applies: see the [0.5.0](0.5.0.md), [0.5.1](0.5.1.md) and
[0.5.2](0.5.2.md) release notes.
