# Satchel 0.5.1

A fix for Claude showing the old result widget after an upgrade to 0.5.0: query results kept the
0.4.0 look and the answer card stayed on "Waiting for the result…".

> **Status:** pre-alpha. Expect breaking changes between 0.x releases. No migrations.

## Install

```bash
uv tool install satchel-server     # or: uv tool upgrade satchel-server
```

```bash
docker pull ghcr.io/getsatchel/satchel:0.5.1
helm upgrade satchel oci://ghcr.io/getsatchel/charts/satchel --version 0.5.1 -n satchel -f my-values.yaml
```

## Fixes

- **The widget's URI changes with each build.** It was always `ui://satchel/result`, and MCP Apps
  hosts cache a widget by its URI, so Claude kept the widget it had loaded before the upgrade. The
  URI now carries a hash of the widget (`ui://satchel/result/<hash>`), so a host fetches the new
  widget when the server changes. The unversioned URI still serves the current widget.
- **A widget that gets a card it does not know says so** ("This Satchel card needs a newer widget.
  Start a new chat to load it.") instead of waiting for ever.

## Upgrading from 0.5.0

Update the package or image and restart. On a VM, set `SATCHEL_IMAGE_TAG=0.5.1` in `.env`, then
`docker compose pull && docker compose up -d`.

Then start a **new chat** in Claude: a chat that is already open keeps the tool list it started with.
Nothing changes in the connector settings.

Everything in 0.5.0 applies: see the [0.5.0 release notes](0.5.0.md).
