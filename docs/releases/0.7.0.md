# Satchel 0.7.0

- **Connect an agent** gives setup steps built from the server's own settings. If agents can't
  sign in to this server, or claude.ai can't reach it, it says so and shows what works instead.
- **Gemini** is a model provider: add a Gemini API key under Settings > Models.

> **Status:** pre-alpha. Expect breaking changes between 0.x releases. One migration (0019).

## Install

```bash
uv tool install satchel-server     # or: uv tool upgrade satchel-server
```

```bash
docker pull ghcr.io/getsatchel/satchel:0.7.0
helm upgrade satchel oci://ghcr.io/getsatchel/charts/satchel --version 0.7.0 -n satchel -f my-values.yaml
```

## Changes

### Connect an agent (#67)

Before, the UI showed one set of Claude steps, built from the browser's address. Now
`GET /v1/connect` returns what the server knows:

- the MCP URL, from `SATCHEL_PUBLIC_URL`;
- whether agents can sign in through the identity provider, and which provider it is;
- whether the URL is https on a public host, so claude.ai can reach it.

**Connect an agent** has tabs for Claude, Claude Code, Cursor and other clients.

- **No identity provider:** it says agents can't sign in. It gives the token route instead, with
  `satchel token create --workspace <slug> --user <your email>` filled in.
- **Not public:** it says Claude Desktop and claude.ai can't reach the server, and points to
  Claude Code.
- **Cursor:** always uses a personal access token.
- **Different address:** an admin who opened the UI at an address other than the public URL is
  warned, because sign-ins and tokens are bound to the public URL.

You find it in four places:
- on Home;
- in the Dashboard's Set up list;
- in the Dashboard's Agent activity card;
- in the command palette.

### Gemini (#68)

- **Settings > Models** has a **Gemini** provider. It takes a Gemini API key from Google AI Studio
  and calls Google's OpenAI-compatible endpoint. The default model is `gemini-2.5-flash`.
- **Deployment:** set `SATCHEL_CHAT_PROVIDER=gemini`. The key comes from the first of these that
  is set: `SATCHEL_CHAT_API_KEY`, `GEMINI_API_KEY`, `GOOGLE_API_KEY`.
- **Evals:** pin a suite with `model: { provider: gemini, name: ... }`, or run with
  `--model gemini:<name>`.

Gemini is for curation and evals. Embeddings are configured separately, and Gemini isn't one of
their providers.

## Upgrading from 0.6.x

There is one migration. Where it runs:
- **Helm:** the chart's pre-upgrade job runs it.
- **VM:** `docker compose up -d` runs it in the `db-upgrade` step before the server restarts.
- **Installed package:** run `satchel db upgrade` before restarting.

Migration 0019 lets `llm_connection.provider` be `gemini`. Downgrading it deletes Gemini
connections.

On a VM:
1. Set `SATCHEL_IMAGE_TAG=0.7.0` in `.env`.
2. Run `docker compose pull && docker compose up -d && docker image prune -a -f`
   ([One VM: Operate](../deploy/vm.md#6-operate)).

Everything in [0.6.0](0.6.0.md) applies when upgrading from 0.5.x.
