# Satchel 0.6.0

The curator UI is reorganised around what Satchel knows and where it learns it.

- **Observability** is its own page, with answer quality, adoption, grounding, performance and
  workflow adherence.
- **Connections** have their own page and a guided setup that writes the warehouse SQL for you.
- **Every create and edit form** opens as a panel on the right, and it no longer loses what you typed.
- **New sources default to Preview**, so nothing publishes on its own.

> **Status:** pre-alpha. Expect breaking changes between 0.x releases. No migrations.

## Install

```bash
uv tool install satchel-server     # or: uv tool upgrade satchel-server
```

```bash
docker pull ghcr.io/getsatchel/satchel:0.6.0
helm upgrade satchel oci://ghcr.io/getsatchel/charts/satchel --version 0.6.0 -n satchel -f my-values.yaml
```

## Changes

### Navigation

The sidebar is now:

| Group | Pages |
|---|---|
| Curate | Inbox, Library, Agent instructions, Releases |
| Observe | Sessions, **Observability**, Evals |
| Data | Catalog |
| **Setup** | **Connections**, Sources, Settings |

Old links redirect:
- `/settings?tab=connections` → `/connections`;
- `/sessions?tab=usage` → `/observability`.

### Observability (#63)

A new page with one time range and six tabs:

| Tab | What it shows |
|---|---|
| **Overview** | Headline numbers with the change from the previous period |
| **Quality** | Thumbs up/down by week and client, doubted, low-confidence and caveated answers, recent thumbs down |
| **Adoption** | Questions and people over time, new vs returning, a people table |
| **Grounding** | Governed metric vs raw SQL, answers that read context, metrics and tables asked about, context never served |
| **Performance** | p50/p95 and errors per tool, warehouse queries per connection, slowest calls |
| **Adherence** | Whether agents followed Satchel's workflow, by rule and by client, with recent misses |

The Dashboard's **Agent activity** card shows Questions, Thumbs up, Governed and Adherence, each
with its change. Every measure is defined in [Observability](../concepts/observability.md), and
the API is `GET /v1/observability/analytics?days=7|30|90` (curators).

### Connections and the Catalog (#61, #62)

- **Guided setup.** **Add connection** opens a panel in four named steps: Kind · Details ·
  Prepare · Crawl.
  - Prepare shows the setup SQL for the warehouse (or `gcloud` commands for BigQuery), filled in
    with your names.
  - For Snowflake, the browser generates the key pair. Only the public key appears, in the SQL.
    The private key is sealed on the server and never shown.
  - For PostgreSQL, the browser generates the password the same way.
  - Generation needs HTTPS or `localhost`. **Use my own key** still takes a pasted key.
- **Snowflake fixes:**
  - A key encrypted with an empty passphrase now loads.
  - **Database** refuses `DB.SCHEMA` and says to put the schema in Schemas.
  - **Test** also reads the database's `INFORMATION_SCHEMA`, so a wrong database fails at Test,
    not at the crawl.
  - A failed test ends with a hint naming the field to check.
- **Catalog.** The connection cards are replaced by a Connection filter. Each table's panel shows
  where it comes from: its warehouse, the sources that describe it, and when it was last seen.

### Forms (#61, #64)

- **Create, edit and inspect forms** are panels on the right. Each has its own URL (`?sheet=new`,
  `?sheet=<id>`, `?sheet=edit`), so Back closes it and a link reopens it. After you type
  something, Esc or a click outside asks "Discard your changes?".
- **Confirms** stay small and centred. They don't close on Esc while you've typed a reason, and
  their titles are questions.
- **Eval suites** can be edited from the suite view.
- **Models:** the form puts Provider first and uses **Add model** and **Remove**.

### Sources publish to preview by default (#65)

A new source, from the UI, API, CLI or `satchel.config.yaml`, defaults to `publish: preview`. A
sync leaves a preview release for a curator to publish. `publish: auto` still publishes on every
sync.

### Deployment (#57, #58)

- `/healthz` and `/readyz` report the running version and widget URI. `satchel status` shows the
  server's version and flags a mismatch with the CLI.
- The EKS Terraform module now uses **EKS Pod Identity** by default, instead of IRSA. Pod
  Identity needs no IAM OIDC provider, which some organisations' SCPs deny.
- Other EKS fixes from a real deploy:
  - exec auth for the Kubernetes and Helm providers;
  - a plan no longer fails on a sensitive `chat_api_key`;
  - the Helm releases are uninstalled before the NAT gateway on destroy, so `terraform destroy`
    no longer hangs;
  - Free plan settings are documented.

## Upgrading from 0.5.x

Update the package or image and restart. On a VM, set `SATCHEL_IMAGE_TAG=0.6.0` in `.env`, then
`docker compose pull && docker compose up -d && docker image prune -a -f`
([One VM: Operate](../deploy/vm.md#6-operate)). Start a new chat in Claude to pick up the new
widget.

- **Sources:** existing sources keep the publish mode they were saved with. A source declared in
  `satchel.config.yaml` without `publish` becomes `preview` at its next import. Add
  `publish: auto` to keep publishing on every sync.
- **EKS with Terraform:** `workload_identity` now defaults to `pod_identity`. To keep IRSA on an
  existing cluster, set `workload_identity = "irsa"` before you apply. Otherwise the apply moves
  the pods to Pod Identity: it adds associations, changes the role trust policies and removes
  the module's OIDC provider. Fargate always uses IRSA.
- **Bookmarks:** the redirects above cover the moved pages.

Everything in 0.5.0 to 0.5.4 applies: see the [0.5.0](0.5.0.md), [0.5.1](0.5.1.md),
[0.5.2](0.5.2.md), [0.5.3](0.5.3.md) and [0.5.4](0.5.4.md) release notes.
