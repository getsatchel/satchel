# Satchel 0.3.0

Background work now runs from a Postgres job queue, so a deploy or a crash no longer loses an
eval run, a sync or a curation pass. Claude Desktop and claude.ai custom connectors can sign in,
the curator UI moves to a new palette and leads with summaries, and a new guide deploys Satchel on
one VM.

> **Status:** pre-alpha. Expect breaking changes between 0.x releases. This release deletes
> `user_memory` items: see [Upgrading from 0.2.0](#upgrading-from-020).

## Install

```bash
uv tool install satchel-server     # or: uv tool upgrade satchel-server
satchel init --example jaffle
satchel up
```

Container image and Helm chart:

```bash
docker pull ghcr.io/getsatchel/satchel:0.3.0
helm install satchel oci://ghcr.io/getsatchel/charts/satchel --version 0.3.0 -n satchel --create-namespace -f my-values.yaml
```

This release ships with `satchel-adapter-sdk` 1.2.1 (IR 1.0.0).

## New

- **Job queue.** Eval runs, source syncs, push webhooks, connection crawls and curation passes are
  queued in Postgres (the `job` table) instead of running inside a web request or a thread.
  - Any number of web servers and workers share the queue (`FOR UPDATE SKIP LOCKED`). A claimed
    job holds a lease that a heartbeat renews, so a job whose process dies is picked up again.
  - Failed attempts are retried with backoff, up to each kind's limit.
  - **Sync now**, **Run curation** and push webhooks return at once (`202`) and the work runs in
    the background. `?wait=true` keeps the old in-request behaviour.
  - Syncs run from the CLI or a CI upload are recorded too, so a source's **Recent syncs** lists
    every sync.
  - New settings: `SATCHEL_WORKER_JOB_THREADS` and `SATCHEL_WEB_JOB_THREADS` (2 each; `0` turns a
    process's consumer off) and `SATCHEL_JOB_POLL_S` (5). See [Configuration](../deploy/configuration.md).
- **Jobs page** and `GET /v1/jobs`, `GET /v1/jobs/{id}`, `POST /v1/jobs/{id}/retry`: what is
  queued, running, failed or done, with a retry for failed jobs.
- **Duplicate suggestions merge.** Open suggestions that propose exactly the same change are merged
  into the oldest one, which keeps all their evidence. Suggestions a curator has already acted on
  are left alone.
- **One-VM deployment.** [`deploy/vm/`](../../deploy/vm/) runs Postgres, the server, the worker
  and Caddy (automatic HTTPS) with Docker Compose, in production mode with OIDC sign-in. The
  [guide](../deploy/vm.md) covers EC2 and Amazon Cognito, and choosing an embedding provider for
  a 2 GiB machine.

## Changes

- **Claude custom connectors sign in.** Claude Desktop and claude.ai identify themselves with a
  client ID metadata document that also lists the `jwt-bearer` grant type. Satchel refused the
  whole document and answered "Unknown or invalid client_id". It now drops grant types it does not
  support (dynamic registration too) and logs why a metadata document is rejected.
- **`user_memory` removed.** Satchel serves only shared, reviewed context; a user's own
  preferences belong to their agent client. The item type, its serving in context packs and the
  `memory_convergence` hygiene check are gone. Saved `memory_min_users` and `memory_similarity`
  settings are ignored.
- **Curator UI.**
  - A near-black on off-white palette with one cobalt accent replaces cream and cognac, in light
    and dark.
  - The session inspector leads with the agent's answer, one line per tool call.
  - Library and Sources rows are quieter; detail panels lead with what you act on.
  - Changes groups unpublished changes by origin (UI edits, the context repo, each source) and
    folds large groups.
  - The Dashboard shows four action numbers per section; Catalog shows coverage once.
  - The sidebar fits a 900 px tall screen.
- **Docs.** `<!-- site: … -->` markers place the website's interactive diagrams, and every
  screenshot in `docs/screenshots/` is recaptured.

## Upgrading from 0.2.0

**Back up the database first.** Migration `0014` deletes every `user_memory` item, its versions
and whatever points at them. It cannot be undone.

```bash
uv tool upgrade satchel-server
satchel db upgrade
```

The migrations are `0014` (remove `user_memory`), `0015` (the `job` table) and `0016` (job
results). Run `satchel db upgrade`, or let the Helm chart's migration job run, before starting the
new version.

After the upgrade:

- Web servers run queued jobs as well as the worker. To keep background work off the web tier,
  set `SATCHEL_WEB_JOB_THREADS=0` and run `satchel worker`.
- Scripts that call `POST /v1/curate/run` or **Sync now** and expect the result in the response
  should add `?wait=true`, or poll `GET /v1/jobs/{id}`.
